# FPGA/PYNQ Pitfalls

| 现象 | 优先检查 | 验证方法 | 失效边界 |
|---|---|---|---|
| 仿真正确但板上不更新 | `.bit/.hwh` 是否同名、是否强制下载 | 重启内核或调用 `download()` | 不适用于没有 Overlay 的裸机工程 |
| 采样率比预期低 | Block Design 参数是否覆盖 RTL 常数 | 用首尾采样时间计算实际速率 | 若软件读取本身很慢，需要先排除 PS 侧开销 |
| ROM 正常、实时是常数 | 导联是否插入、输入是否悬空 | 看 DRDY/帧数是否变化 | 不能替代示波器检查模拟前端 |
| 采集超时但缓冲区有数据 | 是否把上一次缓存当本次结果 | 每次启动前清零或带采样批次号 | 只读缓存无法证明数据新鲜 |
| 红心标在 T 波或毛刺上 | 阈值、 refractory、输入异常 | 用黄金 R 峰和 CLT 曲线逐拍比对 | 不同患者的形态需要重新标定 |
| 批量验证结果“变差” | 参考时间轴是否对齐、脚本是否旧版 | 比较脚本哈希、参数和记录级对齐率 | 对齐失败不等于检测算法失败 |
| 100 MHz 时序失败 | 组合路径和真实采样带宽 | 看 timing.rpt 的路径簇 | 不能靠降低时钟掩盖功能错误 |
| 直接自动重写多个源文件 | 版本基线和 testbench 是否同步 | 先小样例生成、再 diff | 批量替换只适合可回滚的实验分支 |
