# Prompt Templates

## 1. 现象定位

```text
现象：<只写观测到的现象和数字>
当前版本：<RTL/BD/bit 文件时间或版本>
已做验证：<仿真、寄存器、波形、接线>
希望你先给出：最可能的 3 个原因、每个原因的最小验证方法、如何回退。
不要先重写代码。
```

## 2. 版本不一致

```text
请比较以下两个版本的功能差异，不要只看文件名：
源文件时间、关键参数、仿真结果、生成 bit 的时间、BD 参数覆盖情况。
输出一张“证据 -> 结论 -> 仍需验证”的表。
```

## 3. 时序与资源

```text
这是 timing.rpt 和 util.rpt。
先提取 WNS/WHS、失败端点、LUT/FF/BRAM/DSP。
再判断是否存在真实性能需求；如果提高时钟没有应用收益，请明确指出。
```

## 4. 输出验收

```text
请把修改拆成一个最小补丁，并给出：
1) 仿真命令和期望日志；
2) 上板只读检查；
3) 失败时的回退条件；
4) 哪些文件绝对不能动。
```
